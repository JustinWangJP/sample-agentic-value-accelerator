# ドメイン文書

エンジニアリング系スキルがコードベースを調査する際に、このリポジトリのドメイン文書をどう参照するかを定める。

## 調査前に読むもの

- リポジトリルートの **`GLOSSARY.md`**
- **`docs/adr/`**: これから作業する領域に関係する ADR を読む。

これらのファイルが存在しない場合は**何も言わずに先へ進む**。存在しないことを指摘したり、事前に作成を提案したりしない。用語や決定事項が実際に確定した時点で、`/domain-modeling` スキル（`/grill-with-docs` や `/improve-codebase-architecture` 経由で呼ばれる）が必要に応じて作成する。

## ファイル構成

このリポジトリは single-context 構成とする。

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-yyy.md
├── platform/
└── applications/
```

## 用語集（glossary）の語彙を使う

出力の中でドメイン概念に名前を付けるとき（Issue タイトル、リファクタリング提案、仮説、テスト名など）は、`GLOSSARY.md` で定義された用語を使う。用語集が明示的に避けている同義語に流れないこと。

必要な概念が用語集にまだない場合、それはシグナルである。プロジェクトで使われていない言葉を作り出していないか見直すか、本当に欠けている用語として `/domain-modeling` 向けに記録する。
